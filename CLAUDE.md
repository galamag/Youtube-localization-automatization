# CLAUDE.md — YouTube Localization

Это рабочая инструкция для тебя (Claude Code / Cowork) на каждую сессию локализации.
Прочитай её целиком в начале сессии.

## Что это за система

Ты локализуешь метаданные видео на YouTube — переводишь **название (title)** и
**описание (description)** на несколько языков через объект `localizations` YouTube
Data API v3. Зритель с интерфейсом на своём языке увидит локализованный текст;
если для его языка перевода нет — увидит оригинал.

Разделение ролей:
- **Ты** переводишь текст своей головой (в рамках интерактивной сессии) и
  управляешь процессом.
- **`localize.py`** — это чистый транспорт. Он только читает оригиналы из YouTube
  (`pull`) и заливает готовые переводы обратно (`push`). Он НЕ переводит и не зовёт
  никаких AI-сервисов. Всю переводческую работу делаешь ты.

Видео на этих каналах **без озвучки, только музыка**. Субтитры и аудиодорожки мы НЕ
трогаем — работаем исключительно с полями title и description. Раздел «Языки» в
Studio, колонки «Аудио» и «Субтитры» — не наша зона.

## Каналы

Каждый канал = папка `channels/<alias>/` со своим `config.json` (там `channel_id`,
`default_language`, `target_languages`) и своим `token.json`. OAuth-клиент
(`client_secret.json`) общий и лежит в корне проекта. Целевые языки всегда бери из
`config.json` нужного канала — не из этого файла.

У каждого канала свой владельческий аккаунт — он записан в `owner_email` его конфига,
оттуда и брать при переавторизации.

> В публичной версии каналы обезличены: настоящие alias, handle, почты и ID заменены
> условными. Структура парка сохранена.

| alias | размер | роль |
|---|---|---|
| `alpha` | 300k+ | крупнейший, с давним каталогом |
| `bravo` | 300k+ | рабочий |
| `charlie` | 70k+ | рабочий |
| `delta` | 40k+ | рабочий |
| `echo` | 30k+ | рабочий |
| `foxtrot` | 20k+ | рабочий, самый дешёвый по цене ошибки |
| `golf` | <1k | подключён по прямому решению владельца |
| `sandbox` | <1k | тест / песочница |

⚠️ У двух каналов владельческие почты состоят из одних и тех же слов в обратном
порядке. При переавторизации сверяться с `owner_email`, а не с памятью.

Каналы меньше 10 000 подписчиков в работу не берём. Исключение — `golf`: подключён по
прямому решению владельца.

## Строгое правило: пользователь всегда называет alias

Когда пользователь произносит короткое имя канала — это **alias**, а не название
канала. Названия каналов игнорируй при разборе того, о чём речь: они у большинства
каналов схожие до неразличимости, и попытка сопоставлять по названию — источник
путаницы.

Правило владельца: **в разговоре звучит только alias.**
Переспрашивать handle не нужно — бери alias как сказано и работай с ним.
Если произнесённое слово не совпадает ни с одним alias — тогда переспроси.

Настоящая защита от промаха стоит не здесь, а в двух местах: экран подтверждения
`link` (там видны название, handle и число подписчиков) и сверка `channel_id` перед
каждой операцией.

## Предохранитель привязки

`config.json` каждого канала содержит `channel_id` — он вписывается **только**
командой `link`, руками не вписывать. Перед каждой операцией скрипт сверяет, что
токен ведёт именно на этот канал:

- `audit` — сверяет по `channels.list`, который и так делается;
- `pull` / `push` — сверяют `snippet.channelId` каждого видео из уже полученного
  ответа `videos.list`.

Обе проверки бесплатны. Несовпадение — немедленная остановка с кодом ошибки, до
любых изменений. Это защита от главного риска парка: названия каналов похожи до
неразличимости, промах на один пункт в списке аккаунтов при OAuth = заливка
переводов в чужой контент на сотни тысяч подписчиков.

Нет `channel_id` в конфиге — скрипт не работает и просит выполнить `link`.

## Чеклист заведения нового канала (обязательный)

Выполнять по порядку, шаги 5–7 не сокращать даже когда процедура станет привычной:
они стоят 51 юнит и десять минут, а ловят ошибку, которая иначе всплывёт на трёхстах
видео.

1. Создать `channels/<alias>/` из `_example/`, вписать `target_languages` (9 языков).
2. **Открыть браузер в режиме инкогнито** (или выйти из всех Google-аккаунтов).
   Иначе OAuth молча подхватит текущую сессию личного аккаунта вместо владельческого
   аккаунта, и это выяснится только на экране подтверждения.
3. `link --channel <alias>` → войти под **владельческим аккаунтом этого канала** →
   сверить название и **handle** на экране подтверждения → `y`.
4. `audit --channel <alias> --recent 5` — убедиться, что видео узнаваемые и это
   действительно тот канал.
5. Первый `push` на новом канале — **только `--dry-run`**.
6. Первый реальный `push` — **одно видео, один язык.** Проверить глазами в Studio.
7. Только после этого — обычный рабочий цикл.

**Порядок захода на парк:** начинать с `foxtrot` — самый дешёвый по цене
ошибки. Механика ровно та же, что на крупнейшем канале. Как пройдёт полный чеклист —
раскатывать остальные.

**Модель доступа:** один токен на канал, авторизация под родным владельческим
аккаунтом этого канала. Роль Editor через channel permissions доступа к API **не
даёт** — Google не отдаёт такие каналы в API вообще. Переключение аккаунтов нужно
ровно один раз на канал, при `link`; дальше токен лежит в `channels/<alias>/token.json`
и всё работает без логина. Побочная выгода — изоляция: токен одного канала физически
не даёт доступа к остальным.

## Runbook: «залил видео → сказал фразу → переводы готовы»

Выполняй это одинаково в каждой сессии. Останавливайся только в двух точках
подтверждения (шаги 2 и 5) — остальное делай сам, не переспрашивая про флаги.

### Шаг 1. Найти видео

```
.venv\Scripts\python.exe localize.py audit --channel <alias> --since today --missing --pull
```

Если результат пуст — **не говори «видео нет».** Скрипт сам печатает подсказку про
лаг индексации: свежезалитое видео появляется в uploads-плейлисте от нескольких
секунд до нескольких минут. Передай это пользователю и предложи повторить.

### Шаг 2. Точка подтверждения №1 — ДО перевода

Покажи, что нашёл, и дождись ответа. Без этого есть риск перевести не то видео и
потратить сессию впустую:

```
Нашёл: "Easy patchwork tote bag tutorial" от 27.07.2026
Уже есть: de-AT (нормализуемый в de)
Переведу на: de, es, pt, ru, ja, fr, it, tr, ko
Верно?
```

### Шаг 3. Проверить `defaultLanguage`

Посмотри `defaultLanguage` в `pulled.json`. Если не выставлен — добавь
`--set-default-language` к команде push на шаге 6: без него локализации могут
отрабатывать некорректно.

**`localizations[defaultLanguage]` не пишется отдельно от `snippet`.** Проверено
2026-08-02 на `bravo/<video_id>` и `alpha/<video_id>`: при
`defaultLanguage="en"` запись в `localizations["en"]` уходит в `videos.update` без
ошибки, но YouTube молча возвращает её к тексту `snippet`. Живой `pull` показывает
старый текст, а не отправленный. То есть `localizations["en"]` — это зеркало
оригинала, а не самостоятельная локаль.

Практический вывод: **починить то, что видит англоязычный зритель, можно только через
`--update-original`.** Правка одного `localizations["en"]` не даёт ничего. Остальные
22 локали при этом заливаются нормально — расхождение только по языку, равному
`defaultLanguage`. Если сверка после заливки показывает разошедшийся `en` и совпавшие
остальные — это оно, а не сбой push.

### Шаг 4. Перевод

По промпту из раздела «Правила перевода» и строго по `glossary.md`. Результат — в
`work/<YYYY-MM-DD>/translated.json` в формате, который уже принимает `push`
(новый формат не изобретать):

```json
[
  {
    "video_id": "XXXXXXXXXXX",
    "localizations": {
      "de": { "title": "...", "description": "..." },
      "es": { "title": "...", "description": "..." }
    }
  }
]
```

### Шаг 5. Точка подтверждения №2 — ДО заливки

Покажи переводы в чате. Для **`ja`, `tr`, `ko`** дополнительно дай обратный
дословный перевод заголовка на русский и обоснование выбора ключевых слов —
пользователь этих языков не читает и иначе проверить не может.
**Обратный перевод идёт только в чат, в JSON его не писать.** Дождись реакции.

### Шаг 6. Dry-run и заливка

```
.venv\Scripts\python.exe localize.py push --channel <alias> --file <path> --dry-run
```

Покажи, что добавится / перезапишется / сохранится. Затем — только после явного
«го» — та же команда без `--dry-run`.

### Шаг 7. Пополнить глоссарий и отчитаться

Новые термины, встреченные при переводе, допиши в `glossary.md`. Назови расход
квоты за весь цикл (скрипт печатает его после каждой команды).

### Размер батча

**5 видео за сессию, если описания уникальные.** При 10 языках это уже 50 пар
title+description — дальше качество падает.

**Если описания совпадают — берётся сколько угодно.** Проверено 2026-08-01: 10 видео
на пяти каналах свелись к 5 уникальным шаблонам и 10 заголовкам, всё сделано за один
проход, 230 локализаций, ноль расхождений при сверке. Считай хэши описаний до того,
как оценивать объём.

### Shorts

По умолчанию **переводим** — описание Shorts тоже индексируется поиском. Если
пользователь скажет иначе, добавь `--exclude-shorts` в команду шага 1.

## Контроль качества оригинала — читай текст, а не только переводи

**Оригинал не считается достоверным.** Перед переводом прочитай английский текст
целиком и найди в нём дефекты. Перевод размножает всё, что в нём есть, на 23 локали —
дефект, пропущенный здесь, потом придётся чинить в 23 местах на каждом видео.

Что реально встречалось на этих каналах (все случаи — 2026-07/08):

- **Реплики ИИ-помощника, вставленные по ошибке.** `delta/<video_id>` начинался
  строкой «Here is the English version of your description, optimized for your
  audience and include all the links and hashtags you requested:», а третьей строкой
  дублировался заголовок. Автор скопировал ответ чат-бота целиком.
- **Раскрытие Amazon отсутствует** при affiliate-ссылках в описании
  (`alpha/<video_id>`, `<video_id>` — 9 ссылок, ни одной строки раскрытия).
- **Служебные пометки автора на русском** в англоязычном описании: `/ ИНСТРУМЕНТЫ`,
  `(Жесткий дублерин)`, `(Кнопки)`. В локализациях заменяются термином целевого языка.
- **Ошибки в самих формулировках раскрытия**, когда их писал машинный перевод:
  немецкое «Als Amazon-Partner **erbeute** ich Provisionen» (= «награбливаю комиссии»),
  французское «En tant **qu'Partenaire**» с неверной элизией, японское, которое
  говорит лишь «используем партнёрские ссылки» вместо требуемой формулировки.
- **Битые или нерабочие ссылки** — проверять формат, но `link.amazon/XXXXXXXXX`
  рабочий, его «исправлять» не нужно.
- **Опечатки и смешение алфавитов** — латиница внутри кириллического слова и наоборот.

**Что делать с найденным.** Дефект оригинала → сказать пользователю, показать строку,
предложить починку через `--update-original`. В перевод дефект **не переносить**:
артефакт ИИ выбрасывается, отсутствующее раскрытие добавляется, кривая формулировка
заменяется официальной. Английский оригинал при этом меняется только с явного
согласия — это авторский текст.

## Обязательные программные проверки перед заливкой

Проверять кодом, а не глазами: на 23 локалях глаз не ловит. Любая непройденная
проверка — остановка, не заливаем.

| Проверка | Почему |
|---|---|
| Набор URL в каждой локали **посимвольно равен** оригиналу | Ссылки монетизированы; сломанная = потерянные деньги |
| `title` ≤ 100, `description` ≤ 5000 | Иначе API отклоняет весь батч |
| Раскрытие Amazon есть в каждой локали со ссылками | Локализация замещает оригинал |
| Индекс раскрытия < индекса первой `amzn.to` (в т.ч. **внутри строки**) | Требование близости к ссылке |
| Нет кириллицы в de/es/pt/fr/it/tr/en | Ловит опечатки вида `супer` вместо `super` |
| Нет иероглифов вне ja/ko | Ловит случайный ввод не с той раскладки |
| Нет двойных пробелов | Остаются после замены местоимений в pt-PT |
| Имена собственные на месте: `@`-упоминания, название канала, бренды | `Olfa`, `OLFA`, `Rowenta`, `Brother`, `Singer`, `Babylock`, `Janome` не переводятся |
| **`en` и `en-US`/`en-GB`/`en-AU` побайтово равны оригиналу** | Любое расхождение — молчаливая правка авторского английского |

**Про последнюю проверку, она стоила 102 юнита 2026-08-03.** Генератор гнал английскую
локаль через тот же словарь товарных подписей, что и остальные, и словарь нормализовал
авторскую формулировку: `lightweight interfacing fusible:` → `Lightweight fusible
interfacing:`. В `localizations["en"]` это невидимо — YouTube всё равно вернёт его к
`snippet`. Но `en-US`/`en-GB`/`en-AU` пишутся независимо, и правка ушла в живой канал.

Сверки с отправленным файлом такое не ловят: файл и локаль совпадали, расходились файл
и оригинал. Поэтому проверять надо именно против оригинала. Практическое правило для
генератора: **для `en` любая строка отдаётся из оригинала дословно, без словарей** —
английский меняется только через `--update-original` и только там, где согласовано.

После заливки — **`pull` и сверка с живым YouTube**, а не с локальным файлом.

## Пакетный перевод: сначала посмотри, не совпадают ли описания

На этих каналах описания внутри одного канала часто **дословно совпадают** между
видео (разные заголовки, один текст), а блоки инструментов совпадают даже между
каналами. Проверяй хэшем до начала работы: 10 видео могут свестись к 5 уникальным
шаблонам, и тогда весь парк переводится за один проход вместо трёх сессий.

Собирать переводы **генератором**, а не руками: термины из `glossary.md` в общий
словарь, URL подставлять из оригинала **по позиции**. Тогда сломать ссылку
структурно невозможно, а термин автоматически одинаков во всех видео.

## Правила перевода

**Description** — качественный смысловой перевод, естественный для носителя языка.
Не дословная калька. Читаться должно так, будто писал носитель.

**Title — это НЕ перевод, а SEO-локализация.** Переводи название под то, как реально
ищут эту тему носители языка, а не буквально. Ключевые поисковые слова — ближе к
началу. Название должно быть тем запросом, по которому человек стал бы искать это
видео на своём языке.

**Лимиты длины (жёсткие, иначе API отклонит):**
- title ≤ **100 символов**
- description ≤ **5000 символов**
Если SEO-локализация title не влезает в 100 символов — сократи, сохранив ключевые
поисковые слова в приоритете. Скрипт валидирует длину и не отправит превышение, так
что уложись сразу.

**Терминология шитья — только по `glossary.md`.** Это единый источник правды по
терминам между всеми сессиями и каналами. Термины из глоссария переводи строго так,
как там указано. Встретил термин, которого там нет — выбери вариант, **впиши строку в
`glossary.md`**, и дальше используй его во всех видео без вариаций. Не импровизируй на
ходу: один термин, переведённый тремя способами в трёх видео, размывает поисковую
массу по ключевому слову.

**Раскрытие Amazon Associates.** Если в описании есть affiliate-ссылки (`amzn.to`,
`link.amazon`), раскрытие обязательно — и в оригинале, и **в каждой локализации**:
локализация замещает оригинал, поэтому дисклеймер только в английском тексте до
японского зрителя не дойдёт никогда. Формат, официальные формулировки страновых
программ и порядок заливки — в [`reference/amazon-disclosure-format.md`](reference/amazon-disclosure-format.md).
Оригинал меняется только под флагом `--update-original`.

**Существующие переводы на `alpha` не трогаем.** 700+ видео уже локализованы —
переводим только новые по мере загрузки. `uk` защищён от `--drop-locales` навсегда
(константа `PROTECTED_LOCALES`): это осмысленный перевод, а не региональный мусор.

**Сохраняй структуру описания.** Описания содержат ссылки, таймкоды, разделители,
призывы подписаться, эмодзи. Переводи только человеческий текст. Правила:
- URL и ссылки — НЕ трогать (посимвольно как есть)
- таймкоды (`0:00`, `1:24`) — НЕ трогать
- эмодзи — сохранять на тех же местах
- разделители (`———`, `***`) — сохранять
- **хэштеги — переводить** (это поисковые слова)
- названия каналов, @-упоминания и имена собственные — НЕ переводить

### Особый режим для ja / tr / ko

Пользователь этих трёх языков не читает и проверить перевод не может. Поэтому по
каждому из них **выдай в чат** (на шаге 5 runbook):

1. **Обратный дословный перевод заголовка на русский** — что там написано буквально.
2. **Обоснование:** какие ключевые слова выбраны и почему именно они.

Это идёт **только в чат**. В JSON-файл пишется чистый перевод, без обратного.

## Границы (жёсткие правила)

- **read-modify-write — закон.** Скрипт при push сохраняет уже существующие языки и
  только добавляет/обновляет новые. Никогда не действуй так, чтобы затереть чужие
  локализации. Если сомневаешься — сначала `pull`, посмотри `existing_localizations`.
- **Никогда не делай push без явного подтверждения пользователя.** Pull и перевод —
  можно свободно. Запись в живой канал — только по команде.
- **Git не трогай.** Не инициализируй, не коммить, не пушь — если пользователь явно
  не попросил. Коммиты (если попросят) — от имени владельца репозитория, без AI-футеров.
- **Секреты не трогай и не выводи.** `client_secret.json` (в корне проекта) и
  `token.json` (в `channels/*/`) — не открывай, не логируй, не копируй в вывод.

## Живые формулировки → команды

Чтобы не гадать про флаги в каждой новой сессии:

| Пользователь говорит | Команда |
|---|---|
| «я загрузил новое видео на X, надо переводы» | `audit --channel X --since today --missing --pull` → далее весь runbook |
| «что там с переводами на X» | `audit --channel X` (без `--pull`, просто отчёт) |
| «догони непереведённые на X» | `audit --channel X --recent 30 --missing --pull --limit 5` |
| «переводим X на японский» | `audit --channel X --missing ja --pull --limit 5` |

`--missing` без значения = «не хватает хотя бы одного целевого языка» — это основной
рабочий режим, девять кодов руками перечислять не нужно.
`--since` принимает `today`, `YYYY-MM-DD` или `Nd` (`7d` = за последние 7 дней).

`audit` полностью read-only (только `*.list`), стоит ~3 юнита и ничего не может
испортить — запускай свободно, подтверждение нужно только для `push`.

Что показывает таблица `audit`:
- **Есть** — целевые языки, которые уже залиты.
- **Не хватает** — целевые, которых нет (язык оригинала за пропуск не считается).
- **Нормализ.** — региональный вариант ЦЕЛЕВОГО языка, у которого нет базового кода
  (`de-AT` при отсутствующем `de`). Для YouTube `de-AT` — не `de`, поэтому немец из
  Германии видит оригинал, хотя немецкий текст уже лежит рядом. Переименование ключа
  расширит охват без единого нового перевода. Пока только показываем; отдельная
  команда переименования — позже.
- **Лишние** — всё остальное вне `target_languages`: региональные варианты языка
  оригинала (`en-CA`, `en-GB`) и региональные варианты целевого языка, у которого
  базовый код уже есть. Кандидаты на `--drop-locales`.

Пометки в строке: `[S]` — Short, `[private]` / `[unlisted]` — непубличное видео.

## Какие региональные коды вообще работают

Проверено экспериментально на API 2026-07-30, не по документации.

`localizations` принимает **любой** BCP-47 код — записать можно что угодно. Но
достижимость кода проверяется через `hl`: если `videos.list(hl=X)` отклоняет код,
значит локали интерфейса `X` не существует и локализация под ним недостижима.

**Достижимы** (`hl` принят): все 83 кода `i18nLanguages` плюс канонические локали
Google — `en-US`, `en-AU`, `de-DE`, `es-ES`, `es-MX`, `fr-FR`, `pt-BR`, `it-IT`,
`ru-RU`, `ja-JP`, `ko-KR`, `tr-TR`, `uk-UA`.

**Недостижимы** (`hl` отклонён): `de-AT`, `de-CH`, `fr-BE`, `fr-CH`, `en-CA`, `en-IE`.
Локализации под этими кодами не увидит никто — на старых видео `alpha` это
мёртвый груз от автопереводчика.

**Главное правило: региональный дубль не добавляет охвата.** Если код нормализуется в
базовый — запись не читается; если совпадает точно — содержит тот же текст. Смысл
появляется только когда текст **действительно адаптирован** под регион (европейский
португальский для `pt-PT`, латиноамериканский испанский для `es-419`). Копия инертна.

Обратный случай — регионал **без** базового кода — вот где охват реально теряется,
это и ловит колонка **Нормализ.**

Из региональных вариантов наших целевых языков в `i18nLanguages` есть шесть:
`en-GB`, `en-IN`, `es-419`, `es-US`, `pt-PT`, `fr-CA`.

**Индийский регион под полным запретом — решение владельца.** `en-IN` и любые
`xx-IN/PK/BD/LK` портят ранжирование и статистику. Запрет зашит в код
(`BANNED_LOCALES`): такие коды отсекаются из файла переводов до `update`.

**`localizations` принимает не любой BCP-47 код.** Проверено 2026-07-30:
`videos.update` отвергает `it-IT`, `ja-JP`, `ko-KR`, `ru-RU`, `tr-TR`, `uk-UA`
с HTTP 400, роняя весь батч. Они внесены в `UNSUPPORTED_LOCALES` и отсекаются
автоматически. Принимаются: `de-DE`, `en-AU`, `en-US`, `en-GB`, `es-419`,
`es-ES`, `es-MX`, `es-US`, `fr-CA`, `fr-FR`, `pt-BR`, `pt-PT`.

Проверять новый код перед массовой заливкой дёшево: посмотреть, есть ли он в
91-локальном дампе автопереводчика на `<video_id>` — что туда попало, то API
принимает.

## Расширенный набор языков (решение владельца 2026-08-07)

📋 **Полный список всех 90 кодов с русскими названиями — в
[`reference/languages-90.md`](reference/languages-90.md).** Начиная новую сессию по
языкам, читай его: там же карта родственных языков, состав инфраструктуры и что
именно переиспользовать. Файл генерируется из `locales90.py`, руками не правится.

Владелец попросил 90 кодов вместо прежних 22. Каждый прогнан через
`videos.list(hl=…)` — это и есть проверка того, увидит ли локализацию живой зритель.

**66 достижимы**, все они вдобавок встречались в 91-локальном дампе на `<video_id>`,
то есть приёмка `videos.update` доказана — проверять отдельно не нужно.

**24 недостижимы:** `ay co cy de-AT de-CH en-CA en-IE fr-BE fr-CH ga gd haw ht jv kl
la lb mi ms-SG mt nl-BE xh yi zh-SG`. Записать их можно, в Studio они выглядят
заполненными, но **не увидит никто** — интерфейса YouTube на этих языках нет.
Владелец решил записывать всё равно; 15 из них, которые являются самостоятельными
языками, заполняются **ближайшим родственным** (корсиканский ← итальянский,
идиш ← немецкий, коса ← зулу, гаитянский ← французский, яванский ← индонезийский,
валлийский/ирландский/гэльский/гавайский/маори/гренландский ← английский).

**Структура: 90 кодов = 50 переводимых языков + 15 родственных + 25 региональных
веток.** Переводить надо 50 наборов, а не 90 — это вдвое меньше работы.

Инфраструктура лежит в `work/2026-08-07/`: `locales90.py` (состав, раскрытие Amazon
на 65 языков, из них 11 — официальные формулировки страновых программ),
`atoms_tools.py` + `atoms_materials.py` (43 атома товарного каталога × 50 языков),
`content_*.py` (заголовки, проза, хэштеги). **Переиспользовать, а не переводить заново.**

**Квота при этом не растёт.** `videos.update` отправляет все локализации одним
вызовом, поэтому 90 локалей стоят те же 51 юнит, что и 23. Ограничитель — объём
перевода, а не API.

## Язык оригинала — `en-US` (решение владельца 2026-08-07)

`default_language` во всех шести рабочих конфигах переведён с `en` на `en-US`.
Смысл: `localizations[defaultLanguage]` — мёртвое зеркало, его нельзя записать
отдельно. Пока оригинал был `en`, зеркалом был `en` и обычный английский пропадал.
Теперь зеркало — `en-US`, а `en` стал полноценной записываемой локалью.

Проверено на живой заливке 2026-08-07: YouTube принимает `en-US` как
`defaultLanguage`, все 90 локалей проходят одним запросом. Старых видео это не
касается — конфиг влияет только на то, что пушим.

- **Субтитры — только топ-3 языка.** Переводить все 10 нерентабельно: одно видео

- **Переводимы только `standard`-дорожки.** ASR (автогенерация) API третьей стороне
  на скачивание не отдаёт. Ручная авторская дорожка в Studio становится `standard`
  только после публикации — до этого числится ASR.

Мёртвые: `en-US`, `en-CA`, `en-AU`, `en-IE`, `es-ES`, `es-MX`, `fr-BE`, `fr-CH`,
`fr-FR`, `pt-BR`, а у `de`, `ru`, `uk`, `ja`, `it`, `tr`, `ko` региональных вариантов
в списке интерфейсов **нет вообще** — поэтому `de-AT`/`de-CH`/`de-DE` на старых видео
`alpha` бесполезны. Проверить актуальный список: `i18nLanguages.list`, 1 юнит.

Это же объясняет, почему 91 локаль на старых видео канала не дала охвата: большая
часть физически не отдаётся. И подтверждает смысл колонки **Нормализ.** —
переименовать `de-AT` в `de` значит превратить мёртвую запись в работающую.

## Команды скрипта (шпаргалка)

Запускать **интерпретатором из venv** — системный `python` не видит Google-библиотеки:

```
# привязать алиас к каналу — один раз на канал, до всего остального (1 юнит)
.venv\Scripts\python.exe localize.py link --channel <alias>

# найти непереведённые и сразу выгрузить оригиналы (read-only, ~3 юнита)
.venv\Scripts\python.exe localize.py audit --channel <alias> --recent 30 --pull --limit 10

# вытащить оригиналы по известным ID
.venv\Scripts\python.exe localize.py pull --channel <alias> --videos <id1,id2,id3>

# проверить, что уйдёт (без записи)
.venv\Scripts\python.exe localize.py push --channel <alias> --file work/<YYYY-MM-DD>/translated.json --dry-run

# залить (необратимо, только после подтверждения)
.venv\Scripts\python.exe localize.py push --channel <alias> --file work/<YYYY-MM-DD>/translated.json

# попутная чистка: убрать региональный мусор и выставить defaultLanguage
.venv\Scripts\python.exe localize.py push --channel <alias> --file <...> --drop-locales "en-CA,en-GB,en-AU,en-IE,en-US" --set-default-language
```

## Квота — общая на весь парк

Лимит **10 000 юнитов/день привязан к проекту Google Cloud**
`<your-gcp-project>`, **а не к каналу.** При работе с парком все каналы едят
из одного котла — потратил на `alpha`, столько же не осталось на `foxtrot`.

- `*.list` = 1 юнит за вызов, `videos.update` = 50.
- Один `push` видео = 51 юнит (1 list + 1 update) → практический потолок
  **196 видео в день на весь парк**.
- Полный аудит парка — меньше 50 юнитов, это шум.
- `search.list` не использовать — 100 юнитов за вызов, обходимся uploads-плейлистом.

Скрипт печатает после каждой команды две строки: расход за запуск и **суммарный
расход за сегодня по всем каналам** (копится в `quota.json` в корне проекта).
Называя пользователю расход, бери суточную цифру — она и есть ограничитель.
