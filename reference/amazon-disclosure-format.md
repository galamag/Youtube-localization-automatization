# Эталон формата: раскрытие Amazon Associates в описаниях

Зафиксировано на `<video_id>` (канал `alpha`, 2026-07-30) — первое видео,
приведённое к этому формату. От него строится массовая вставка дисклеймера по каналу.

## Правило размещения

Решение владельца (2026-07-30): раскрытие должно стоять **перед affiliate-ссылками**,
выносить его в первые строки описания не требуется. Обоснование: сами ссылки тоже
находятся под сворачиванием «ещё», поэтому любой, кто раскрыл описание, встретит
раскрытие раньше ссылок — требование близости к рекламной ссылке выполняется.

**Оригинал (`snippet.description`):** строка раскрытия — под заголовком **каждого**
блока с affiliate-ссылками (`Tools & Equipment Used:`, `Materials:`), непосредственно
перед ссылками этого блока. Так сделано на эталонном `<video_id>`: заголовок →
раскрытие → пустая строка → ссылки.

**Каждая локализация:** две строки — локальная формулировка, под ней английская.

⚠️ **Фактический формат парка — не верхний, а поблочный.** Проверено 2026-08-03 на уже
залитых видео (`<video_id>` и др.): раскрытие стоит не сверху описания, а под
заголовком **каждого** блока со ссылками, в скобках, ровно там же, где оно стоит в
оригинале:

```
✂️ <переведённый заголовок блока>:
(<локальная формулировка>
As an Amazon Associate I earn from qualifying purchases)

<ссылки блока>
```

Так структура локализации совпадает со структурой оригинала строка-в-строку, что даёт
бесплатную проверку: число строк локали = число строк оригинала + по одной на каждый
блок раскрытия. Верхнее размещение критерий близости тоже выполняет, но парк уже
живёт в поблочном формате — **следовать ему**, иначе видео разъедутся по оформлению.

**Проверка вместо правила о первой строке:** номер строки первого раскрытия должен быть
меньше номера строки первой `amzn.to` / `link.amazon`. Это и надо проверять программно.

## Английский текст меняется только через `--update-original`

Проверено 2026-07-30 на `<video_id>`: когда `defaultLanguage = en`, YouTube держит
`localizations["en"]` синхронно с `snippet.description` — они побайтово равны, а
отдельная запись в `localizations["en"]` игнорируется.

Практический вывод для массовой вставки дисклеймера: класть английский текст в
`localizations["en"]` бесполезно, нужен блок `snippet` в файле и флаг
`--update-original`. Для остальных языков — обычные `localizations`.

Почему две строки: аккаунт владельца в US-программе, её Operating Agreement требует
английской формулировки; FTC требует понятности потребителю. Две строки закрывают оба
требования сразу.

Почему в каждой локализации: локализации работают на **замещение** — зритель с японским
интерфейсом видит японское описание вместо английского, и дисклеймер только в оригинале
до него не дойдёт никогда.

## Английская строка (обязательна везде)

```
As an Amazon Associate I earn from qualifying purchases.
```

## Локальные формулировки

Взяты из Operating Agreement страновых программ Amazon, не переведены самостоятельно.
Для `ru`, `uk`, `ko` страновых программ нет — перевод свой, английская строка обязательна.

## Как заливать

Оригинал меняется только под флагом `--update-original` — без него блок `snippet`
из файла игнорируется. Формат файла:

```json
[{"video_id": "...", "snippet": {"description": "..."}, "localizations": {...}}]
```

## Цена массовой операции

На канале `alpha` 700+ видео. Один `push` = 51 юнит → **~36 000 юнитов**, то есть
минимум **4 дня** при лимите 10 000/сутки на весь парк. Планировать с этим расчётом.

## Жёсткое правило

URL не трогать ни в каком виде — ни `amzn.to`, ни `link.amazon`, ни ссылки на YouTube.
Формат `link.amazon/XXXXXXXXX` рабочий, «исправлять» его не нужно. Подписи к товарам
переводятся, ссылки — нет. Сверять программно до заливки.
